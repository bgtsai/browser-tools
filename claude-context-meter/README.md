# Claude 上下文用量（claude-context-meter）

在 claude.ai 跑 Claude Code 遠端工作階段（Cowork／Project 對話）時，畫面上顯示這個對話串目前的上下文用量，
並在「換新對話串比較划算」或用量過高時主動提醒。不需要 hook、不需要使用者手動跑 `/context`。

> v0.x 是開發中版本，介面是暫定的最簡版。

## 為什麼要估算（2026-11-12 實測結論）

瀏覽器端拿得到的三個來源，沒有一個直接給「目前上下文」：

| 來源 | 內容 | 能不能當上下文 |
|---|---|---|
| `/v1/code/sessions/<id>`（工作階段 GET） | 整個工作階段的累計 token，每輪結束才更新，還含背景工作 | 不能，拆不出單次呼叫 |
| `ConversationService/StreamTimeline`（protobuf 串流） | 額度使用率、時間戳、訊息內容 | 不能，沒有 token 欄位 |
| `chat_conversations/<id>?tree=true`（對話樹） | 完整對話內容（文字、工具呼叫、工具結果、附件） | 可以估算 |

`/context` 是本機指令：不呼叫模型，但輸出會進到模型的上下文（約 3 千 token），所以只能偶爾送。

## 程式結構

```
fetch 攔截 ──► 看到工作階段 GET（＝一輪結束）──► 節流後 refresh()
                                                     │
               對話樹 ◄── 主動抓 /chat_conversations/<id>?tree=true
                 │
                 ├─ 沿 current_leaf 走出目前分支（trunk）
                 ├─ 找最近一次 /context 的輸出（助理訊息以「## Context Usage」開頭）→ 校正點
                 └─ 估算字數 → token：中日韓字 1 字≈1、其他 3.5 字元≈1
                       │
                       ▼
   C ＝ F ＋ k × 目前估算
     有校正點時這等同「/context 總量 ＋ k ×（之後新增的估算）」
     沒校正點時 F、k 取最近一次在任何對話串的校正值，沒有就用預設
     F ＝ /context 總量 − 訊息（固定部分：系統提示詞、工具、MCP、技能）
     k ＝ /context 的訊息 ÷ 校正點之前的估算（修正分詞器與看不到的內容）
                       │
                       ▼
   判斷（01 第⑫條）：B ＝ F ＋ R ＋ H ＋ W，N* ＝ (1.25 × B) ÷ (0.1 × (C − B))
     下一階段預估輪數 ≥ N* → 建議換串；用量 ≥ 70% 起每 +10% 提醒一次
                       │
                       ├─► 畫面右下角小標籤（暫定）
                       └─► 自動送 /context（見下）
```

### 自動送 `/context` 的時機

只在輸入框是空的時候送（不動使用者沒送出的字），每個對話串最多 3 次、間隔至少 15 分鐘：

1. 這個對話串還沒有校正點，而且已經有至少 2 則訊息。
2. 估算用量 ≥ 65%，且上次校正時還不到 60%（要提醒之前先確認準確值）。

### 預設值（可在程式開頭的 `CFG` 改）

| 項目 | 值 | 說明 |
|---|---|---|
| F | 135,000 | 2026-11-12 實測：系統提示詞 72.6k＋工具 13.8k＋MCP 41.3k＋說明 2.4k＋技能 4.8k |
| k | 1.82 | 同日實測：訊息 269.5k ÷ 估算 148.1k |
| R | 42,000 | 新對話串要讀的規則（01 的 read_kb 輸出＋速查卡） |
| H | 5,000 | 交接內容 |
| W | 40,000 | 新對話串要重讀的工作資料 |
| 下一階段輪數 | 15 | 新功能約 15～30、小修約 5 |

## 已知限制

- 估算值：k 是用最近一次 `/context` 推出來的，對話內容的組成變了（例如大量讀檔）就會偏。
- 對話被自動壓縮之後，對話樹會不會跟著變短還沒測；不會的話估算會偏高。
- 介面的位置、字級、配色是暫定，還沒照 03 號 UI 原則討論與畫 mockup。
